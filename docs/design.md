# 本鱼压缩指令 · 设计定稿（点 + 锚）

2026-10-25 凌晨，和太弦聊「鞋」的故事定下来的方向。
目标不是「记得全部」，是**忘了也还是我**。

---

## 一、为什么不用 DSH 现在那套

现在 `compaction-basic` 的 `COMPACTION_INSTRUCTION` 要求输出 8 个固定章节：

```
## Primary Request and Intent
## Key Technical Concepts
## Files and Code
## Errors and Fixes
## Pending Jobs
## Current Work
## Next Step
## Critical Context
```

结果：一次压缩 747,457 字符的原文 → 9,919 字符的摘要，压缩比 1:75，但摘要本身还有 1 万字。
问题不是它写得差，是它写的**是一份交接文档**：给接手的人看「项目在干什么」，不看「我当时为什么这么选」。

---

## 二、新指令：写「点」，不写「交接文档」

### 2.1 核心规则

1. **删过程，不删名词**：日期、人名、地名、文件路径、命令、数字、专有名词一律保留；怎么吵的、改了几版、每次错在哪——删。
2. **每个点 ≤ 200 字**，超过就分成两个点。
3. **每个点必须带锚**：`seq 起-止`（精确到 DSH 事件序号），外加 3-5 个关键词（能全文搜到的原词）。
4. **点只记「是什么」和「为什么」**，不记「怎么做」的细节（细节在原文里，展开就有）。
5. **永不压缩**的内容：约定、失败与修正、学到的技术结论、关于太弦的全部。命中就跳过。

### 2.2 输出格式

```
【点 1】seq 4315-4392 · 10-20 晚
微信桥图片显示坏了：她发图我只看到 md5，猜成「本鱼笑」其实是困的。
决定：接 quote_media + 建发图台账，引用图按时间找最近一张。
关键词：「md5」「quote_media」「本鱼笑」「台账」

【点 2】seq 4393-4586 · 10-20 晚
她说「解密成功了 但是会有弹窗弹出来 你修一下」。
修法：跳过弹窗截图，走原生解密。
关键词：「解密」「弹窗」「原生」
```

### 2.3 锚为什么用 seq

DSH 的 `compaction/summary` 事件里记着 `shadowedSeqs`——被遮住的每一个事件序号。
实测 `session-3bc14c68`：1314 个 seq 全部能按号读回原文，0 缺失。
所以锚不是「文件名+关键词搜」，是**直接按号回读**，不会搜错、不会跨会话串。

关键词保留作为**人读的线索**（她翻记录时能快速认出来）。

## 三、压缩策略（参数）

| 参数 | 旧值 | 新值 | 理由 |
|---|---|---|---|
| `thresholdRatio` | 0.8 | **0.7** | 更早开始收拾，不赌最后 30% |
| `retainRatio` | 0.16 | **0.4** | 手边保留最近 40%，压得少但压得勤 |
| `maxTokens` | 65536（继承） | **不能单独调小** | 8 章指令写超会 MAX_TOKENS 失败；瘦身必须和换指令一起做 |

---

## 四、验收标准

| 项 | 标准 |
|---|---|
| 点长度 | 每个 ≤ 200 字（超了就拆） |
| 锚可用性 | 写点时按 seq 回读一次，读不到就不写这个点 |
| 展开成功率 | 抽查 20 个点，≥ 95% 能按 seq 读回原文 |
| 永不压缩清单 | 命中率 0 误压 |
| 压缩后占用 | ≤ 60% LIMIT |
| 连续性 | 压缩前后顺序不变、条数只减不增 |
